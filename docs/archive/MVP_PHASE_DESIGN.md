# MVP 系统分阶段执行方案与核心页面设计

> 目标：将业务流程拆解为两阶段执行方案，并映射为 MVP 系统的 10 个核心页面
> 日期：2025-12-22
> 依据：BUSINESS_FLOW_MANAGEMENT.md

---

## 一、Phase 1 执行版（低冲击 · 防反噬）

### 1.1 目标

```
┌────────────────────────────────────────────────────────────────┐
│                                                                │
│   Phase 1 的核心目标是「照亮」，而不是「问责」                  │
│                                                                │
│   - 让问题「可见」，而不是立即惩罚                              │
│   - 建立数据记录习惯，而不是强制限制                           │
│   - 让每个人知道自己该对什么负责（认知层），但不强制执行       │
│   - 给团队适应期，避免因制度过猛导致反噬                       │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```

### 1.2 管理原则

| 原则 | 说明 | 禁止行为 |
|------|------|----------|
| **可见优先** | 系统让数据透明，老板/主管能看到问题 | 不允许系统自动惩罚 |
| **解释责任** | 责任人需解释数据，但不追责 | 不允许因亏损直接问责 |
| **软性提醒** | 异常只高亮提示，不阻断流程 | 不允许自动冻结/停项目 |
| **人工裁决** | 所有重要决策由人做出 | 不允许系统替代人判断 |

### 1.3 核心流程变化（相比原有无系统状态）

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        Phase 1 流程改进                                  │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  【项目启动】                                                           │
│  原来：口头确认负责人                                                   │
│  现在：系统录入项目 + 指定负责人（有记录）                              │
│                                                                         │
│  【充值流程】                                                           │
│  原来：微信群申请，财务直接打款                                         │
│  现在：系统提交申请 → 财务/老板审批（有流程）                           │
│        ⚠️ Phase 1 不强制「无批准不打款」，允许紧急情况绕行              │
│                                                                         │
│  【日报审核】                                                           │
│  原来：投手填日报，没人审核                                             │
│  现在：投手填日报 → 系统高亮异常 → 主管可审核（有监督）                 │
│        ⚠️ Phase 1 不强制主管必须审核，只提供待审提醒                    │
│                                                                         │
│  【周度检查】                                                           │
│  原来：无固定机制                                                       │
│  现在：系统自动生成周消耗汇总 + 项目负责人补充分析（有数据）            │
│        ⚠️ Phase 1 不强制必填，只是提供模板                              │
│                                                                         │
│  【月度结算】                                                           │
│  原来：Excel 手工汇总                                                   │
│  现在：系统生成对账报表 + 财务人工确认（有依据）                        │
│        ⚠️ Phase 1 锁定只是标记，不阻止后续修改                          │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 1.4 管理者应如何使用 Phase 1 系统

| 角色 | 使用方式 | 频率 | 目的 |
|------|----------|------|------|
| **老板** | 看驾驶舱 + 资金总览 | 每日 | 知道钱在哪里 |
| **老板** | 审批充值申请 | 随时 | 控制资金出口 |
| **老板** | 看项目盈亏看板 | 每周 | 知道哪个项目在亏 |
| **主管** | 审核日报 + 标记异常 | 每日 | 发现投手问题 |
| **项目负责人** | 提交周度简报 | 每周 | 解释项目进展 |
| **财务** | 更新资金表 + 对账 | 每周/月 | 保证数据准确 |

**Phase 1 的关键心态：**
```
不是用系统「管人」，而是用系统「看清问题」
发现问题后，老板/主管自行决定如何处理
系统只负责让信息透明，不负责惩罚
```

## 二、Phase 2 执行版（强化治理 · 引入责任）

### 2.1 相比 Phase 1 新增的约束

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        Phase 2 新增约束                                  │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  【充值审批】                                                           │
│  ✗ 紧急绕行 → ✓ 严格执行「无批准不打款」                                │
│  新增：超预算自动阻断申请                                               │
│                                                                         │
│  【日报审核】                                                           │
│  ✗ 可选审核 → ✓ 主管必须每日审核                                        │
│  新增：连续3天 CPL 超标自动触发「暂停建议」                             │
│  新增：未填日报自动提醒 + 记入考核                                      │
│                                                                         │
│  【周度简报】                                                           │
│  ✗ 可选提交 → ✓ 周五下班前必须提交                                      │
│  新增：未提交周报的项目自动标记「管理缺失」                             │
│                                                                         │
│  【项目管理】                                                           │
│  ✗ 无预算约束 → ✓ 必须有预算才能启用                                    │
│  新增：消耗达到预算 80% 自动预警                                        │
│  新增：超预算自动暂停充值申请                                           │
│                                                                         │
│  【月度结算】                                                           │
│  ✗ 可修改 → ✓ 锁定后不可修改                                            │
│  新增：对账差异必须标注责任归属                                         │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 2.2 责任与纠偏机制如何升级

| 机制 | Phase 1 | Phase 2 |
|------|---------|---------|
| **CPL 不达标** | 高亮提示 | 连续3天自动触发暂停建议 |
| **消耗异常** | 仅展示 | 超日均 30% 自动警告 |
| **充值超预算** | 人工判断 | 系统自动阻断 |
| **周报未交** | 提醒 | 记入项目负责人考核 |
| **对账差异** | 人工裁决 | 必须指定责任方 |
| **项目亏损** | 老板自行处理 | 连续两月亏损强制复盘 |

**纠偏权升级：**
```
Phase 1                          Phase 2
───────                          ───────
主管：看到问题 → 沟通            主管：看到问题 → 暂停账户权限
项目负责人：解释进展             项目负责人：承担盈亏责任
老板：自由决策                   老板：按规则执行（终止/追责）
```

### 2.3 哪些行为在 Phase 2 才允许执行

| 行为 | Phase 1 禁止原因 | Phase 2 允许条件 |
|------|------------------|------------------|
| 暂停投手账户 | 避免冲突 | 主管有审核记录 + 连续异常 |
| 冻结项目充值 | 避免业务中断 | 超预算 + 老板确认 |
| 绩效扣分 | 无数据依据 | 日报/周报数据积累 |
| 更换项目负责人 | 无明确责任 | 连续亏损 + 复盘记录 |
| 终止项目 | 决策太重 | 月度复盘 + 老板正式决定 |

**Phase 2 启动前提：**
```
1. Phase 1 已运行至少 2 个月
2. 日报填报率 > 90%
3. 周报提交率 > 80%
4. 团队对责任划分无重大异议
```

## 三、MVP 系统的 10 个核心页面

> 按老板优先级排序：先解决「钱在哪里」和「项目赚不赚」

---

### 页面 1：老板驾驶舱（Dashboard）

**页面目标**
```
让老板一眼看清公司整体状态，不用翻多个页面
回答问题：今天公司怎么样？有什么需要我关注的？
```

**使用角色**
| 角色 | 权限 |
|------|------|
| 老板 | 查看全部数据 |
| 项目负责人 | 查看自己负责的项目汇总 |

**核心数据字段**
| 字段 | 说明 | 来源 |
|------|------|------|
| 本月总消耗 | 所有项目消耗合计 | ad_spend_daily |
| 本月总进粉 | 所有项目进粉合计 | daily_report |
| 整体 CPL | 总消耗 / 总进粉 | 计算 |
| 预计毛利 | 预计收入 - 预计成本 | project_pnl |
| 资金余额合计 | 所有账户余额 | 资金表 |
| 活跃项目数 | 状态=进行中 | project |
| 异常项目数 | CPL 超标或亏损 | 计算 |
| 待审批充值数 | 状态=待审批 | topup_request |
| 本周消耗趋势 | 7天日消耗折线图 | ad_spend_daily |
| Top 5 消耗项目 | 按消耗排序 | 聚合 |

---

### 页面 2：资金总览（Fund Overview）

**页面目标**
```
让老板随时知道「钱在哪里」
回答问题：公司的钱都花到哪了？还有多少余额？能收回多少？
```

**使用角色**
| 角色 | 权限 |
|------|------|
| 老板 | 查看全部 |
| 财务 | 查看全部 + 编辑更新 |
| 项目负责人 | 查看自己项目 |

**核心数据字段**
| 字段 | 说明 | 来源 |
|------|------|------|
| 项目名称 | 项目唯一标识 | project |
| 负责人 | 资金使用责任人 | project |
| 累计充值 | 该项目总充值金额 | topup_record |
| 累计消耗 | 该项目总消耗金额 | ad_spend_daily |
| 账户余额 | 充值 - 消耗 | 计算 |
| 应收款 | 客户应付金额 | 结算表 |
| 已回款 | 客户已付金额 | 财务记录 |
| 未回款 | 应收 - 已回 | 计算 |
| 资金占用天数 | 从充值到回款 | 计算 |
| 代理商 | 账户所属代理商 | ad_account |

### 页面 3：项目盈亏看板（Project P&L）

**页面目标**
```
让老板/项目负责人看清每个项目的盈亏状态
回答问题：哪个项目在赚钱？哪个在亏钱？亏多少？
```

**使用角色**
| 角色 | 权限 |
|------|------|
| 老板 | 查看全部 |
| 项目负责人 | 查看自己负责的项目 |
| 主管 | 查看团队相关项目 |

**核心数据字段**
| 字段 | 说明 | 来源 |
|------|------|------|
| 项目名称 | 项目唯一标识 | project |
| 负责人 | 结果责任人 | project |
| 业务类型 | 自投/代投 | project |
| 本月消耗 | 月度消耗合计 | ad_spend_daily |
| 本月进粉 | 月度进粉合计 | daily_report |

| 状态标签 | 盈利/持平/亏损 | 计算 |

### 页面 4：充值审批（Topup Approval）

**页面目标**
```
资金出口管控，建立「无批准不打款」的流程
回答问题：谁在申请钱？为什么需要？该不该批？
```

**使用角色**
| 角色 | 权限 |
|------|------|
| 项目负责人 | 提交申请 |
| 财务 | 审核（检查预算、余额） |
| 老板 | 最终批准 |

**核心数据字段**
| 字段 | 说明 | 必填 |
|------|------|------|
| 申请日期 | 提交时间 | 系统生成 |
| 项目 | 充值用于哪个项目 | ✓ |
| 金额（USD） | 申请充值金额 | ✓ |
| 代理商 | 充值到哪个代理商 | ✓ |
| 账户 | 具体账户（可选） | - |
| 申请人 | 项目负责人 | 系统生成 |
| 申请理由 | 为什么需要充值 | ✓ |
| 当前余额 | 该项目账户当前余额 | 系统计算 |
| 项目预算 | 该项目总预算 | 系统读取 |
| 已用预算 | 该项目已充值金额 | 系统计算 |
| 财务审核 | 通过/拒绝/备注 | 财务填写 |
| 老板审批 | 批准/拒绝/备注 | 老板填写 |
| 状态 | 待审核/已批准/已拒绝/已打款 | 系统更新 |

---

### 页面 5：日报审核（Daily Report Review）

**页面目标**
```
主管监控投手每日产出，及时发现异常
回答问题：投手今天干得怎么样？有没有异常？需不需要介入？
```

**使用角色**
| 角色 | 权限 |
|------|------|
| 投手 | 填报自己的日报 |
| 主管 | 审核团队日报 + 标记异常 |
| 项目负责人 | 查看项目相关日报 |

**核心数据字段**
| 字段 | 说明 | 填写人 |
|------|------|--------|
| 日期 | 投放日期 | 投手 |
| 投手 | 投放执行人 | 系统 |
| 项目 | 所属项目 | 投手 |
| 账户 | 投放账户 | 投手 |
| 消耗（USD） | 当日消耗 | 投手 |
| 进粉数 | 当日进粉 | 投手 |
| CPL | 消耗/进粉 | 系统计算 |
| 目标 CPL | 参考值 | 系统读取 |
| 是否异常 | CPL 超标/消耗突增 | 系统判断 |
| 异常原因 | 投手解释 | 投手 |
| 主管备注 | 审核意见 | 主管 |
| 审核状态 | 待审/通过/需关注 | 主管 |

### 页面 10：月度结算（Monthly Settlement）

**页面目标**
```
对账与结算锁定，确保每月数据准确可追溯
回答问题：这个月实际花了多少？赚了还是亏了？差异归谁？
```

**使用角色**
| 角色 | 权限 |
|------|------|
| 财务 | 编辑/提交对账 |
| 老板 | 确认/锁定结算 |
| 项目负责人 | 查看自己项目 |

**核心数据字段**
| 字段 | 说明 | 来源 |
|------|------|------|
| 月份 | 2025-12 格式 | 系统 |
| 项目 | 项目名称 | 系统 |

| 对账差异 | 系统 - 账单 | 计算 |
| 差异归属 | 差异责任方 | 财务标注 |
| 总进粉 | 月度进粉 | daily_report |

| 应收款 | 进粉 × 单价 | 计算 |
| 手续费 | 代理商手续费 | 财务录入 |
| 实际成本 | 消耗 + 手续费 | 计算 |

| 财务确认 | 财务是否确认 | 财务 |
| 老板确认 | 老板是否确认 | 老板 |
| 锁定状态 | 未锁定/已锁定 | 系统 |

## 四、Phase 1 / Phase 2 与页面的对应关系

### 4.1 页面功能阶段表

| 页面 | Phase 1 功能 | Phase 2 新增功能 |
|------|-------------|-----------------|
| 1. 老板驾驶舱 | ✓ 全功能 | 异常自动预警推送 |
| 2. 资金总览 | ✓ 全功能 | 资金占用预警 |
| 3. 项目盈亏看板 | ✓ 全功能 | 连续亏损强制标记 |
| 4. 充值审批 | 流程记录（可绕行） | 无批准不打款（强制） |
| 5. 日报审核 | 可选审核 + 高亮 | 必须审核 + 暂停建议 |
| 6. 周度简报 | 可选提交 | 必须提交 + 考核关联 |
| 7. 项目管理 | ✓ 全功能 | 预算必填 + 超预算阻断 |
| 8. 投手管理 | ✓ 全功能 | 绩效关联 |
| 9. 消耗明细 | ✓ 全功能 | - |
| 10. 月度结算 | 可修改 | 锁定后不可修改 |

### 4.2 开发优先级建议

**Phase 1 第一批（核心 MVP）**
```
优先级 P0 - 必须上线：
├── 页面 1：老板驾驶舱
├── 页面 2：资金总览
├── 页面 3：项目盈亏看板
└── 页面 7：项目管理

优先级 P1 - 流程核心：
├── 页面 4：充值审批
├── 页面 5：日报审核
└── 页面 9：消耗明细
```

**Phase 1 第二批（完善功能）**
```
优先级 P2 - 管理增强：
├── 页面 6：周度简报
├── 页面 8：投手管理
└── 页面 10：月度结算
```

**Phase 2 功能升级**
```
在 Phase 1 稳定运行 2 个月后：
├── 充值审批：启用强制阻断
├── 日报审核：启用暂停建议
├── 周度简报：启用必填检查
├── 项目管理：启用预算约束
└── 月度结算：启用锁定机制
```

## 五、这套拆解如何真正实现管理目标

### 5.1 谁对钱负责？

```
┌─────────────────────────────────────────────────────────────────────────┐
│                          资金责任链                                      │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   充值申请          财务审核          老板批准          资金使用        │
│  （项目负责人）    （财务）          （老板）        （项目负责人）     │
│       │               │                │                │              │
│       ↓               ↓                ↓                ↓              │
│   页面 4          页面 4           页面 4           页面 2/3          │
│   充值审批        充值审批         充值审批         资金总览/盈亏      │
│                                                                         │
│   Phase 1：有记录，可绕行                                               │
│   Phase 2：无批准不打款                                                 │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘

✓ 每一笔钱都有申请记录
✓ 每一笔钱都有审批记录
✓ 每一笔钱的使用效果可追溯
✓ 项目负责人对资金使用效率负责
```

### 5.2 谁对结果负责？

```
┌─────────────────────────────────────────────────────────────────────────┐
│                          结果责任链                                      │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   项目层面                                                              │
│   ├── 页面 7（项目管理）：指定项目负责人                                │
│   ├── 页面 3（项目盈亏）：展示项目盈亏，负责人可见                      │
│   └── 页面 6（周度简报）：负责人必须解释进展                            │
│                                                                         │
│   投手层面                                                              │
│   ├── 页面 8（投手管理）：指定直属主管                                  │
│   └── 页面 5（日报审核）：主管监督投手产出                              │
│                                                                         │
│   Phase 1：责任清晰，但不强制问责                                       │
│   Phase 2：责任 + 考核 + 后果                                           │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘

✓ 每个项目都有明确负责人
✓ 负责人必须定期汇报进展
✓ 盈亏结果对负责人可见
✓ 主管对投手产出负监督责任
```

### 5.3 谁能在过程中纠偏？

```
┌─────────────────────────────────────────────────────────────────────────┐
│                          纠偏机制                                        │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   日级纠偏（主管）                                                      │
│   ├── 页面 5（日报审核）：发现异常 → 沟通调整                           │
│   └── 触发条件：CPL 超标、消耗突增                                      │
│       Phase 1：提示 + 沟通                                              │
│       Phase 2：暂停建议 + 记录                                          │
│                                                                         │
│   周级纠偏（项目负责人）                                                │
│   ├── 页面 6（周度简报）：发现趋势 → 调整计划                           │
│   └── 触发条件：周盈亏异常、进度落后                                    │
│       Phase 1：自行汇报                                                 │
│       Phase 2：必须汇报 + 决策记录                                      │
│                                                                         │
│   月级纠偏（老板）                                                      │
│   ├── 页面 3（项目盈亏）：确认继续/调整/终止                            │
│   ├── 页面 10（月度结算）：锁定结果，明确责任                           │
│   └── 触发条件：月度亏损、资金风险                                      │
│       Phase 1：老板自由裁决                                             │
│       Phase 2：按规则执行                                               │
│                                                                         │
│   随时纠偏（老板）                                                      │
│   ├── 页面 1（驾驶舱）：发现重大异常                                    │
│   └── 页面 4（充值审批）：拒绝高风险充值                                │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘

✓ 问题在日级被发现（不用等月底）
✓ 趋势在周级被关注（提前预警）
✓ 结果在月级被确认（责任落实）
✓ 老板随时可介入（不失控）
```

## 六、总结：从流程到系统的完整映射

```
┌─────────────────────────────────────────────────────────────────────────┐

│   MVP 核心页面（10个）完整覆盖：                                         │

```
