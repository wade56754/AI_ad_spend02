## 🚀 P2.2 执行脚本

### 脚本 1: 添加 CHECK 约束（主脚本）

```sql
-- ============================================================
-- P2.2 添加角色 CHECK 约束
-- 执行环境: 测试环境
-- 执行日期: 2025-11-20
-- 风险等级: 低（空表）
-- ============================================================

BEGIN;

-- 1. 添加 CHECK 约束
ALTER TABLE users
ADD CONSTRAINT check_role_enum
CHECK (role IN ('admin', 'finance', 'account_manager', 'data_operator', 'media_buyer'));

-- 2. 验证约束已添加
DO $$
DECLARE
    constraint_count INTEGER;
BEGIN
    SELECT COUNT(*) INTO constraint_count
    FROM pg_constraint
    WHERE conrelid = 'users'::regclass
      AND conname = 'check_role_enum';

    IF constraint_count = 0 THEN
        RAISE EXCEPTION '约束添加失败: check_role_enum 未找到';
    ELSE
        RAISE NOTICE '✅ 约束添加成功: check_role_enum';
    END IF;
END $$;

-- 3. 查看约束定义
SELECT
    conname AS constraint_name,
    pg_get_constraintdef(oid) AS constraint_definition
FROM pg_constraint
WHERE conrelid = 'users'::regclass
  AND conname = 'check_role_enum';

COMMIT;

-- ============================================================
-- 预期输出:
-- NOTICE: ✅ 约束添加成功: check_role_enum
--
-- constraint_name    | constraint_definition
-- -------------------|--------------------------------------------------
-- check_role_enum    | CHECK (role IN ('admin', 'finance', 'account_manager', 'data_operator', 'media_buyer'))
-- ============================================================
```

## 🔄 回滚方案

### 场景 A: 约束添加失败，事务自动回滚
- 无需手动操作，PostgreSQL 自动回滚 BEGIN 块

### 场景 B: 约束添加成功但需要删除

```sql
-- 删除 CHECK 约束
BEGIN;

ALTER TABLE users
DROP CONSTRAINT IF EXISTS check_role_enum;

-- 验证约束已删除
SELECT COUNT(*) as constraint_exists
FROM pg_constraint
WHERE conrelid = 'users'::regclass
  AND conname = 'check_role_enum';
-- 预期输出: constraint_exists = 0

COMMIT;
```

- 如果任何检查失败，**立即停止执行**

### 3. 与 P2.1 的关系
- **测试环境**: P2.1 跳过 → 直接执行 P2.2（当前）
- **生产环境**: P2.1（角色迁移）→ P2.2（添加约束）
- 生产环境执行 P2.2 前，必须确保 P2.1 迁移已完成

### 4. 后续影响
- ✅ 添加此约束后，所有通过 ORM、SQL 或 API 创建/更新用户的操作都会被数据库层验证
- ✅ 如果应用层代码尝试写入非法角色，数据库会返回约束违反错误
- ✅ 这与 P1 阶段修改的 Pydantic 验证器、SQLAlchemy 模型形成多层防护
