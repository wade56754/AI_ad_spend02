## 第一章 文档定位与约束

### 1.1 本文档职责

DEPLOYMENT.md 定义系统部署与运维约束：

- CI/CD 流程规范
- 环境配置管理
- 发布策略与审批流程
- 回滚流程与锚点设计
- 监控与告警要求

> 引用: ARCHITECTURE.md 第一章 §1.2

### 1.2 本文档不做

本文档不承担以下职责：

- 不定义业务规则（属于 BUSINESS_RULES.md）
- 不定义数据结构（属于 DATA_SCHEMA.md）
- 不定义 API 接口（属于 API_SOT.md）
- 不定义测试策略（属于 TESTING.md）
- 不定义架构设计（属于 ARCHITECTURE.md）

### 1.3 核心原则

| 原则 | 说明 | 级别 |
|-----|------|------|
| 账务数据不可回滚 | ledger_entries 禁止通过回滚覆盖 | MUST |
| 终态数据不可逆 | final_locked 状态数据禁止修改 | MUST |
| 审计链完整性 | 任何部署不得破坏审计追溯能力 | MUST |

> 引用: MASTER.md INV-001「账务只追加，不修改」, BI-01

## 第二章 环境配置

### 2.1 环境定义

| 环境 | 用途 | 数据库 | 访问控制 |
|-----|------|--------|---------|
| development | 本地开发 | 独立实例 | 开发者 |
| staging | 集成测试 | 独立实例 | 开发团队 |
| production | 生产环境 | Supabase 托管 | 受限访问 |

### 2.2 环境变量规范

| 变量 | 级别 | 说明 |
|-----|------|------|
| DATABASE_URL | MUST | 数据库连接字符串 |
| SUPABASE_URL | MUST | Supabase 项目 URL |
| SUPABASE_KEY | MUST | Supabase 匿名密钥 |
| SUPABASE_SERVICE_KEY | MUST | Supabase 服务密钥（仅后端） |
| JWT_SECRET | MUST | JWT 签名密钥 |
| ENVIRONMENT | MUST | 环境标识（dev/staging/prod） |

### 2.3 敏感信息管理

| 约束 | 级别 | 说明 |
|-----|------|------|
| 禁止硬编码密钥 | MUST | 所有密钥通过环境变量注入 |
| 禁止提交 .env 文件 | MUST | .env 必须在 .gitignore 中 |
| 生产密钥独立管理 | MUST | 使用密钥管理服务（如 Vault） |

## 第三章 CI/CD 流程

### 3.1 流水线阶段

```
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│  Lint   │ → │  Test   │ → │  Build  │ → │ Deploy  │ → │ Verify  │
│ (Ruff)  │   │(pytest) │   │(Docker) │   │(Staging)│   │(Smoke)  │
└─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘
                                                │
                                                ▼
                                         ┌─────────────┐
                                         │ Deploy Prod │
                                         │ (审批后)    │
                                         └─────────────┘
```

### 3.2 阶段要求

| 阶段 | 工具 | 通过条件 | 级别 |
|-----|------|---------|------|
| Lint | Ruff | 0 errors | MUST |
| Test | pytest | 覆盖率 >= 80%, 0 failures | MUST |
| Type Check | mypy | 0 errors | MUST |
| Build | Docker | 镜像构建成功 | MUST |
| Deploy Staging | - | 部署成功 | MUST |
| Smoke Test | - | 关键 API 可用 | MUST |
| Deploy Prod | - | 审批通过 | MUST |

### 3.3 分支策略

| 分支 | 用途 | 部署目标 | 保护规则 |
|-----|------|---------|---------|
| master | 主分支 | Production | 禁止直接推送，必须 PR |
| develop | 开发分支 | Staging | 禁止直接推送，必须 PR |
| feature/* | 功能分支 | - | 开发者自由 |
| hotfix/* | 紧急修复 | Production | 必须 PR + 紧急审批 |

### 3.4 PR 审批要求

| 目标分支 | 审批人数 | 额外要求 |
|---------|---------|---------|
| develop | >= 1 | CI 全绿 |
| master | >= 2 | CI 全绿 + QA 签字 |
| hotfix → master | >= 1 | 紧急审批 + 事后复盘 |

## 第四章 发布策略

### 4.1 发布类型

| 类型 | 触发条件 | 审批要求 | 回滚窗口 |
|-----|---------|---------|---------|
| 常规发布 | develop → master PR | 标准审批 | 24 小时 |
| 紧急修复 | hotfix PR | 紧急审批 | 4 小时 |
| 配置变更 | 环境变量修改 | 运维审批 | 立即 |

### 4.2 发布清单

发布前必须确认：

- [ ] CI 流水线全绿
- [ ] 数据库迁移脚本已审核
- [ ] 回滚方案已准备
- [ ] 监控告警已配置
- [ ] 相关 SoT 文档已同步

### 4.3 灰度发布（可选）

| 阶段 | 流量比例 | 持续时间 | 回滚条件 |
|-----|---------|---------|---------|
| 金丝雀 | 5% | 30 分钟 | 错误率 > 1% |
| 扩展 | 25% | 1 小时 | 错误率 > 0.5% |
| 全量 | 100% | - | - |

## 第五章 回滚策略

### 5.1 回滚锚点设计

**核心原则**: 应用层可回滚，数据层不可回滚。

```
┌─────────────────────────────────────────────────────────┐
│                    可回滚层                              │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐     │
│  │ 应用镜像    │  │ 配置变更    │  │ 前端资源    │     │
│  │ (Docker)   │  │ (环境变量)  │  │ (CDN)      │     │
│  └─────────────┘  └─────────────┘  └─────────────┘     │
└─────────────────────────────────────────────────────────┘
                         │
                         │ 回滚边界
                         ▼
┌─────────────────────────────────────────────────────────┐
│                    不可回滚层                            │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐     │
│  │ledger_      │  │ 终态数据    │  │ 审计日志    │     │
│  │entries     │  │(final_locked)│ │             │     │
│  └─────────────┘  └─────────────┘  └─────────────┘     │
└─────────────────────────────────────────────────────────┘
```

> 引用: MASTER.md BI-01「账务记录不可篡改」

### 5.2 回滚类型

| 类型 | 范围 | 执行方式 | 约束 |
|-----|------|---------|------|
| 应用回滚 | Docker 镜像 | 切换镜像版本 | 允许 |
| 配置回滚 | 环境变量 | 恢复旧配置 | 允许 |
| Schema 回滚 | 数据库结构 | 向前兼容迁移 | 有限允许 |
| 数据回滚 | ledger/终态 | - | **禁止** |

### 5.3 禁止的回滚操作

| 禁止操作 | 原因 | 引用 |
|---------|------|------|
| 回滚 ledger_entries 数据 | 破坏审计链 | MASTER.md INV-001 |
| 回滚 final_locked 状态数据 | 违反终态保护 | MASTER.md INV-003 |
| 用旧快照覆盖现有账务 | 账务不可逆 | MASTER.md BI-01 |
| 回滚 Schema 导致数据丢失 | 数据完整性 | - |

> 引用: ASDD 迁移计划 §2.7 DEPLOYMENT.md 回滚锚点设计

### 5.4 Schema 迁移约束

| 约束 | 级别 | 说明 |
|-----|------|------|
| 向前兼容 | MUST | 新版本代码必须兼容旧 Schema |
| 向后兼容 | SHOULD | 旧版本代码最好兼容新 Schema |
| 禁止删除字段 | MUST | 使用废弃标记而非删除 |
| 禁止修改字段类型 | MUST | 新增字段代替 |

### 5.5 回滚流程

```
发现问题
    │
    ▼
┌─────────────────┐
│ 评估影响范围     │
│ - 是否涉及账务？ │
│ - 是否涉及终态？ │
└────────┬────────┘
         │
    ┌────┴────┐
    │         │
    ▼         ▼
涉及账务   不涉及账务
    │         │
    ▼         ▼
禁止回滚   执行应用回滚
使用红冲       │
修正          ▼
         切换镜像版本
              │
              ▼
         验证服务恢复
              │
              ▼
         发布事后复盘
```

## 第六章 监控与告警

### 6.1 关键指标

| 指标 | 阈值 | 告警级别 |
|-----|------|---------|
| API 错误率 | > 1% | P1 |
| API 响应时间 P95 | > 500ms | P2 |
| 数据库连接数 | > 80% | P1 |
| 账务异常事件 | > 0 | P0 |

### 6.2 审计日志要求

| 事件类型 | 必须记录 | 级别 |
|---------|---------|------|
| 账本操作 | 操作者、时间、金额、类型 | MUST |
| 状态变更 | 操作者、时间、原状态、新状态 | MUST |
| 登录事件 | 用户、时间、IP、结果 | MUST |
| 部署事件 | 执行者、时间、版本、环境 | MUST |

### 6.3 告警通知

| 级别 | 响应时间 | 通知方式 |
|-----|---------|---------|
| P0 | 15 分钟 | 电话 + 短信 + 即时通讯 |
| P1 | 1 小时 | 短信 + 即时通讯 |
| P2 | 4 小时 | 即时通讯 |
| P3 | 24 小时 | 邮件 |

## 第七章 灾难恢复

### 7.1 备份策略

| 数据类型 | 备份频率 | 保留周期 | 恢复 RTO |
|---------|---------|---------|---------|
| 数据库全量 | 每日 | 30 天 | 4 小时 |
| 数据库增量 | 每小时 | 7 天 | 1 小时 |
| 审计日志 | 实时 | 永久 | - |

### 7.2 恢复优先级

| 优先级 | 系统组件 | RTO 目标 |
|-------|---------|---------|
| 1 | 账务系统 | 1 小时 |
| 2 | 日报系统 | 2 小时 |
| 3 | 认证系统 | 2 小时 |
| 4 | 报表系统 | 4 小时 |

### 7.3 恢复约束

| 约束 | 说明 | 级别 |
|-----|------|------|
| 禁止覆盖恢复账务数据 | 只能恢复到独立实例验证 | MUST |
| 恢复后审计链检查 | 验证 ledger_entries 完整性 | MUST |
| 数据一致性校验 | balance = SUM(entries) | MUST |
