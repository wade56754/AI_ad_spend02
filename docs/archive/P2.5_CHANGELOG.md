## 核心规范

### 统一响应格式

**成功响应**:
```json
{
  "success": true,
  "code": "OK",
  "message": "操作成功",
  "data": {...},
  "request_id": "uuid",
  "timestamp": "ISO8601"
}
```

**错误响应**:
```json
{
  "success": false,
  "code": "AUTH_401",
  "message": "认证失败",
  "data": null,
  "request_id": "uuid",
  "timestamp": "ISO8601"
}
```

### 关键变更

1. ✅ `code` 字段统一为字符串业务码（非HTTP状态码数字）
2. ✅ 删除所有 `error_code` 字段
3. ✅ HTTP状态码仅通过 FastAPI `status_code` 参数传递
4. ✅ 成功码默认值从 `"SUCCESS"` 改为 `"OK"`
5. ✅ 所有错误码必须引用 `ERROR_CODES.md`

## 重大变更 (Breaking Changes)

### 1. 响应格式变更

**影响**: 所有API端点

**前端适配要点**:
```typescript
// ❌ 旧代码
if (response.code === "SUCCESS") { ... }
if (response.error_code === "AUTH_401") { ... }

// ✅ 新代码
if (response.code === "OK") { ... }
if (response.code === "AUTH_401") { ... }
```

### 2. HTTPException detail 格式

**影响**: 依赖 HTTPException detail 的中间件、日志系统

**前端适配要点**:
```python
# ❌ 旧代码
raise HTTPException(status_code=401, detail="认证失败")

# ✅ 新代码
raise HTTPException(
    status_code=401,
    detail={"code": "AUTH_401", "message": "认证失败"}
)
```

### 3. 自定义异常类默认码

**影响**: 使用自定义异常类的代码

**示例**:
```python
# ❌ 旧代码捕获
except ValidationException as e:
    if e.code == "VALIDATION_ERROR": ...

# ✅ 新代码
except ValidationException as e:
    if e.code == "VALIDATION_001": ...
```
