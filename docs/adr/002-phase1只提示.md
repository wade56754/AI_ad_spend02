# ADR-002: Phase 1 只提示不阻断

> **状态**: accepted
> **日期**: 2025-12-22
> **决策者**: 产品 + 架构组
> **关联**: MASTER.md v4.9 §1.3

---

## 背景

**问题陈述**:
- 系统需要逐步上线，不能一开始就强制所有规则
- 业务团队需要适应期
- 数据质量需要逐步提升
- 硬性阻断可能导致业务停摆

**约束条件**:
- 不能影响正常业务运转
- 需要为Phase 2强制约束做准备
- 需要收集足够的异常数据

---

## 决策

**我们决定**: Phase 1 采用"照亮"策略

| 行为 | Phase 1 | Phase 2（未来） |
|------|---------|----------------|
| 余额不足 | ⚠️ 黄色提示 | 🚫 阻断 |
| 状态流转异常 | ⚠️ 高亮显示 | 🚫 阻断 |
| 对账差异 | ⚠️ 记录+提醒 | 🚫 阻断 |
| 权限越界 | ⚠️ 记录+提醒 | 🚫 阻断 |
| 审批流程 | ⚠️ 提示 | 🚫 强制 |

**核心原则**: 记录事实 + 展示状态 + 提示异常，不强制阻断

---

## 备选方案

### 方案A: 直接强制约束
- **优点**: 数据质量高
- **缺点**: 业务可能停摆
- **结论**: ❌ 不采用

### 方案B: 完全不约束
- **优点**: 无阻力
- **缺点**: 无法发现问题
- **结论**: ❌ 不采用

### 方案C: Phase分阶策略（采纳）
- **优点**: 渐进式、低风险
- **缺点**: Phase 1数据质量较低
- **结论**: ✅ 采用

---

## 影响

### 正面影响
- 业务平滑过渡
- 收集真实异常数据
- 为Phase 2做准备

### 负面影响
- Phase 1期间数据可能不完美（可接受）

### 代码影响

```python
# Phase 1 写法
if balance < required:
    # ⚠️ 只记录和提示，不阻断
    log.warning(f"余额不足: {balance} < {required}")
    notify_user("余额不足提醒", level="warning")
    # 继续执行，不 raise

# Phase 2 写法（未来）
if balance < required:
    # 🚫 阻断
    raise BusinessError(code="BIZ_101", message="余额不足")
```

---

## Phase 2 启用条件

Phase 1 稳定运行 2 个月后，满足以下条件可启用 Phase 2：

- [ ] 异常率 < 5%
- [ ] 用户已适应系统
- [ ] 关键流程已验证
- [ ] 老板确认启用
