# 计划编写指南

## 原则

**Every task must be verifiable.**

计划不是愿望清单，而是可执行、可验证的行动步骤。

## 计划结构

### 1. 目标 (Objective)

清晰的最终目标:

```markdown
## 目标

实现日报审核功能，支持:
- 趋势风控检测
- 项目负责人审批
- 最终锁定

成功标准:
- [ ] 8 状态转换全部实现
- [ ] 单元测试覆盖 > 90%
- [ ] E2E 测试通过
```

### 2. 任务分解 (Tasks)

可执行的任务列表:

```markdown
## 任务

### Task 1: 状态机实现
- [ ] 定义 DailyReportStatus 枚举 (8 状态)
- [ ] 实现状态转换方法
- [ ] 添加转换守卫
- 预估: 2h
- 验证: 单元测试通过

### Task 2: API 端点
- [ ] POST /api/v1/daily-reports/{id}/submit
- [ ] POST /api/v1/daily-reports/{id}/approve
- [ ] POST /api/v1/daily-reports/{id}/lock
- 预估: 3h
- 验证: API 测试通过
- 依赖: Task 1
```

### 3. 依赖分析 (Dependencies)

明确任务依赖:

```markdown
## 依赖图

Task 1 (状态机)
    └─→ Task 2 (API 端点)
           └─→ Task 3 (前端页面)
                  └─→ Task 4 (E2E 测试)
```

### 4. 风险评估 (Risks)

识别和缓解风险:

```markdown
## 风险

### 风险 1: 状态转换复杂度
- 概率: 中
- 影响: 高
- 缓解: 使用状态图可视化，先写测试

### 风险 2: 并发修改冲突
- 概率: 低
- 影响: 高
- 缓解: 使用乐观锁
```

## 任务要素

每个任务必须包含:

| 要素 | 必须 | 说明 |
|------|------|------|
| ID | ✅ | 唯一标识符 |
| 描述 | ✅ | 做什么 |
| 验证条件 | ✅ | 如何确认完成 |
| 预估时间 | ✅ | 需要多久 |
| 依赖 | ⚪ | 依赖哪些任务 |
| 风险 | ⚪ | 潜在风险 |

## 检查清单

- [ ] 目标明确
- [ ] 任务可执行
- [ ] 任务可验证
- [ ] 依赖明确
- [ ] 风险评估
- [ ] 时间估计
