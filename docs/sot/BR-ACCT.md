## 规则详细定义

### BR-ACCT-001: 账户必须归属渠道

#### 业务场景
广告账户是投放的执行单元，每个账户必须关联一个广告渠道（如抖音、快手、百度）。渠道决定了账户的平台属性、API 对接方式和数据同步逻辑。

#### 详细约束
- 📌 **强制**: 每个广告账户必须关联一个 `channel_id`
- 📌 **强制**: `channel_id` 必须引用有效的渠道（`channels.id`）
- ❌ **禁止**: 创建无渠道归属的账户
- ❌ **禁止**: 账户创建后修改所属渠道
- ✅ **允许**: 同一渠道下创建多个账户

#### 前置条件
- 数据状态: 渠道已存在且状态为 active
- 引用: DATA_SCHEMA.md v5.6 §3.2.9

#### 错误码映射
| 违反场景 | 错误码 | HTTP | 错误消息 |
|----------|--------|------|----------|
| 缺少 channel_id | `VALIDATION_001` | 400 | 必须指定广告渠道 |
| 渠道不存在 | `BIZ_002` | 404 | 指定的渠道不存在 |
| 修改渠道归属 | `BIZ_001` | 400 | 账户渠道归属不可修改 |

#### 代码引用
- Service: `backend/services/ad_account_service.py`
- 方法: `create_account()`, `update_account()`

#### Test Intent
| ID | 测试场景 | 输入 | 预期结果 |
|----|----------|------|----------|
| T1 | 创建有渠道账户 | channel_id=有效 ID | 成功 |
| T2 | 缺少渠道 | channel_id=null | `VALIDATION_001` |
| T3 | 渠道不存在 | channel_id=无效 ID | `BIZ_002` |
| T4 | 修改渠道归属 | UPDATE channel_id | `BIZ_001` |

### BR-ACCT-002: 账户分配唯一性

#### 业务场景
广告账户在同一时间点只能分配给一个投手（pitcher），确保账户责任明确、日报归属清晰。账户分配变更时，旧分配自动失效。

#### 详细约束
- 📌 **强制**: 同一时间点，一个账户仅能分配给一个投手
- 📌 **强制**: 分配通过 `ad_accounts.owner_id` 字段实现
- ❌ **禁止**: 同一账户同时分配给多个投手
- ✅ **允许**: 账户重新分配（owner_id 变更）
- ✅ **允许**: 一个投手管理多个账户

#### 前置条件
- 用户角色: `account_manager` 或 `admin` 执行分配
- 数据状态: 目标投手存在且角色为 `pitcher`
- 引用: AUTH_SPEC.md v2.1 §5.1.5

#### 错误码映射
| 违反场景 | 错误码 | HTTP | 错误消息 |
|----------|--------|------|----------|
| 分配给非投手角色 | `BIZ_001` | 400 | 账户只能分配给投手角色 |
| 目标投手不存在 | `BIZ_002` | 404 | 指定的投手不存在 |
| 无权限执行分配 | `AUTH_500` | 403 | 权限不足 |

#### 代码引用
- Service: `backend/services/ad_account_service.py`
- 方法: `assign_account()`, `reassign_account()`

#### Test Intent
| ID | 测试场景 | 输入 | 预期结果 |
|----|----------|------|----------|
| T1 | 分配给投手 | owner_id=pitcher 用户 | 成功 |
| T2 | 分配给非投手 | owner_id=finance 用户 | `BIZ_001` |
| T3 | 目标投手不存在 | owner_id=无效 ID | `BIZ_002` |
| T4 | 重新分配账户 | owner_id: A → B | 成功 + 审计 |

### BR-ACCT-003: 账户状态同步

#### 业务场景
账户状态必须与广告平台实际状态保持同步。系统定期从平台 API 拉取状态更新，确保本地状态反映真实情况，避免在已封禁账户上投放广告。

#### 详细约束
- 📌 **强制**: 账户状态必须与平台实际状态保持同步
- 📌 **强制**: 状态变更必须记录到 `account_status_history` 表
- ✅ **允许**: 手动修正状态（需 admin 权限 + 审计）
- ✅ **允许**: 系统自动同步状态（定时任务）
- 📌 **强制**: Phase 1 仅记录状态差异，不自动阻断

#### 账户状态枚举
| 状态 | 说明 | 允许操作 |
|------|------|----------|
| `new` | 新建账户 | 测试投放 |
| `testing` | 测试中 | 小额测试 |
| `active` | 正常投放 | 全部操作 |
| `suspended` | 平台暂停 | 仅查看 |
| `dead` | 死号（被封） | 余额迁移 |
| `archived` | 已归档 | 仅查看 |

#### 前置条件
- 数据状态: 账户已创建
- 引用: STATE_MACHINE.md v2.8 §6

#### 错误码映射
| 违反场景 | 错误码 | HTTP | 错误消息 |
|----------|--------|------|----------|
| 状态同步失败 | `SYS_001` | 500 | 账户状态同步失败 |
| 状态值非法 | `BIZ_001` | 400 | 无效的账户状态 |

#### 代码引用
- Service: `backend/services/ad_account_service.py`
- 方法: `sync_account_status()`, `update_status()`

#### Test Intent
| ID | 测试场景 | 输入 | 预期结果 |
|----|----------|------|----------|
| T1 | 状态同步成功 | 平台返回 active | 状态更新 + 历史记录 |
| T2 | 状态同步失败 | 平台 API 超时 | `SYS_001` |
| T3 | 手动修正状态 | admin 操作 | 成功 + 审计 |
| T4 | 非法状态值 | status=invalid | `BIZ_001` |

### BR-ACCT-004: 余额不可为负

#### 业务场景
广告账户余额通过账本公式计算，代表账户的可用资金。余额不得为负数，负余额意味着账务异常，需要立即处理。

#### 详细约束
- 📌 **强制**: 账户余额计算公式：`opening_balance + Σtopup - Σad_spend`
- 📌 **强制**: 余额必须 >= 0
- ❌ **禁止**: 余额计算结果为负数
- ✅ **允许**: 余额为零（待充值状态）
- 📌 **强制**: Phase 1 余额为负时仅告警，不阻断

#### 余额公式
```
可用余额 = 期初余额 + Σ(充值到账) - Σ(广告消耗)
```

#### 前置条件
- 数据状态: 账本记录完整
- 引用: LEDGER_SOT.md v1.2, BR-FIN-003

#### 错误码映射
| 违反场景 | 错误码 | HTTP | 错误消息 |
|----------|--------|------|----------|
| 余额计算为负 | `BIZ_101` | 400 | 账户余额不足 |
| 余额异常（数据问题） | `BIZ_001` | 400 | 账户余额异常，请检查账本 |

#### 代码引用
- Service: `backend/services/ledger_service.py`
- 方法: `calculate_balance()`, `check_balance()`

#### Test Intent
| ID | 测试场景 | 输入 | 预期结果 |
|----|----------|------|----------|
| T1 | 余额充足 | 余额 > 消耗 | 成功 |
| T2 | 余额为零 | 余额 = 0 | 成功（告警） |
| T3 | 余额不足 | 消耗 > 余额 | `BIZ_101` |
| T4 | 余额异常 | 账本数据缺失 | `BIZ_001` |

### BR-ACCT-005: 分配记录审计

#### 业务场景
账户分配变更是敏感操作，影响日报归属和绩效统计。所有分配变更必须记录完整的审计日志，确保可追溯性和责任明确。

#### 详细约束
- 📌 **强制**: 账户分配变更必须记录到 `audit_logs` 表
- 📌 **强制**: 审计日志包含：操作人、变更前 owner、变更后 owner、时间戳、IP
- 📌 **强制**: 仅 `account_manager` 或 `admin` 可执行分配变更
- ❌ **禁止**: 直接 UPDATE 数据库绕过审计
- ✅ **允许**: 通过 API 执行分配变更（自动记录审计）

#### 审计日志字段
| 字段 | 类型 | 说明 |
|------|------|------|
| module | VARCHAR | 固定为 "ad_accounts" |
| action | VARCHAR | 固定为 "assign" 或 "reassign" |
| entity_id | VARCHAR | 账户 ID |
| performed_by | UUID | 操作人 ID |
| role | VARCHAR | 操作人角色 |
| ip_address | INET | 操作人 IP |
| payload_before | JSONB | `{"owner_id": "旧投手ID"}` |
| payload_after | JSONB | `{"owner_id": "新投手ID", "reason": "变更原因"}` |

#### 前置条件
- 用户角色: `account_manager` 或 `admin`
- 引用: AUTH_SPEC.md v2.1 §8

#### 错误码映射
| 违反场景 | 错误码 | HTTP | 错误消息 |
|----------|--------|------|----------|
| 非授权角色执行分配 | `AUTH_500` | 403 | 仅户管或管理员可分配账户 |
| 审计日志写入失败 | `SYS_001` | 500 | 系统内部错误 |

#### 代码引用
- Service: `backend/services/ad_account_service.py`
- 方法: `assign_account()`, `_record_assignment_audit()`

#### Test Intent
| ID | 测试场景 | 输入 | 预期结果 |
|----|----------|------|----------|
| T1 | account_manager 分配 | 有权限角色 | 成功 + 审计日志 |
| T2 | pitcher 尝试分配 | 无权限角色 | `AUTH_500` |
| T3 | 验证审计日志完整 | 查询 audit_logs | 包含完整字段 |
| T4 | 重新分配记录 | owner_id 变更 | 两条审计（解绑 + 绑定） |

### BR-ACCT-006: 停用账户禁止操作

#### 业务场景
状态为 `suspended`、`dead` 或 `archived` 的账户不得进行消耗操作，防止在问题账户上浪费预算。这些账户仅允许查看和余额处理。

#### 详细约束
- ❌ **禁止**: `suspended`/`dead`/`archived` 账户提交日报
- ❌ **禁止**: 停用账户发起充值
- ❌ **禁止**: 停用账户进行广告投放
- ✅ **允许**: 查看停用账户数据
- ✅ **允许**: `dead` 账户进行余额迁移

#### 账户状态与操作权限
| 状态 | 提交日报 | 发起充值 | 余额迁移 | 查看数据 |
|------|----------|----------|----------|----------|
| `new` | ❌ | ✅ | ❌ | ✅ |
| `testing` | ✅ | ✅ | ❌ | ✅ |
| `active` | ✅ | ✅ | ❌ | ✅ |
| `suspended` | ❌ | ❌ | ❌ | ✅ |
| `dead` | ❌ | ❌ | ✅ | ✅ |
| `archived` | ❌ | ❌ | ❌ | ✅ |

#### 前置条件
- 数据状态: 账户状态非活跃
- 引用: STATE_MACHINE.md v2.8 §6

#### 错误码映射
| 违反场景 | 错误码 | HTTP | 错误消息 |
|----------|--------|------|----------|
| 停用账户提交日报 | `STATE_400` | 400 | 账户已停用，不允许提交日报 |
| 停用账户发起充值 | `STATE_400` | 400 | 账户已停用，不允许发起充值 |
| dead 账户投放 | `STATE_400` | 400 | 死号账户不允许投放 |
| archived 账户操作 | `STATE_400` | 400 | 已归档账户不允许操作 |

#### 代码引用
- Service: `backend/services/daily_report_service.py`
- 方法: `_check_account_status()`

#### Test Intent
| ID | 测试场景 | 输入 | 预期结果 |
|----|----------|------|----------|
| T1 | active 账户提交日报 | status=active | 成功 |
| T2 | suspended 账户提交日报 | status=suspended | `STATE_400` |
| T3 | dead 账户余额迁移 | status=dead | 成功 |
| T4 | archived 账户操作 | status=archived | `STATE_400` |
