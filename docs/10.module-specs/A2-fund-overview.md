## 1. 模块概述

### 1.1 业务目标

**一句话定义**: 让老板在 5 秒内掌握"钱在哪里？能收回多少？"

**核心价值**:
- 资金可视：一眼看清公司资金全貌
- 风险预警：识别资金占用过高的风险
- 回款追踪：掌握应收款和已回款情况

**解决的问题**:
| 老板问题 | 系统答案 |
|---------|---------|
| 总共充了多少钱？ | 累计充值 |
| 花了多少钱？ | 累计消耗 |
| 账户还剩多少？ | 当前余额 |
| 客户欠我们多少？ | 应收款 |
| 钱被占用了多少？ | 资金占用 |
| 已经回了多少款？ | 累计回款 |

### 1.2 用户角色

| 角色 | 访问权限 | 数据范围 |
|------|---------|---------|
| `ceo` | 全部功能 | 全公司数据 |
| `finance` | 全部功能 | 全公司数据 |
| `project_owner` | 只读 | 自己负责的项目 |
| `supervisor` | 禁止访问 | - |
| `pitcher` | 禁止访问 | - |
| `account_manager` | 只读 | 账户余额部分 |
| `admin` | 只读 | 全公司数据 |

### 1.3 核心用例

```
UC-A2-01: 查看资金概览
  前置: 用户已登录，角色为 ceo/finance
  主流程:
    1. 用户打开资金总览页面
    2. 系统展示 5 个核心资金指标
    3. 系统展示资金流向图
    4. 系统展示按项目/渠道的资金分布
  后置: 用户了解资金全貌

UC-A2-02: 按项目查看资金
  前置: 资金总览页面已加载
  主流程:
    1. 用户切换到"按项目"视图
    2. 系统展示每个项目的充值、消耗、余额
    3. 用户点击某项目行
    4. 跳转到项目详情页
  后置: 用户了解单项目资金情况

UC-A2-03: 按渠道查看资金
  前置: 资金总览页面已加载
  主流程:
    1. 用户切换到"按渠道"视图
    2. 系统展示每个渠道的充值、消耗、余额
    3. 用户可排序、筛选
  后置: 用户了解渠道资金分布

UC-A2-04: 资金预警提示
  前置: 存在资金风险
  主流程:
    1. 系统检测到资金占用率 > 80%
    2. 页面顶部展示预警横幅
    3. 用户点击预警查看详情
  后置: 用户知晓资金风险
```

## 2. 数据需求

### 2.1 数据源 (SoT)

| 数据 | SoT 表 | SoT 字段 | 说明 |
|------|--------|---------|------|
| 充值 | `topup_record` | `amount` | 充值 SoT |
| 消耗 | `ad_spend_daily` | `spend` | Phase 1 消耗 SoT |
| 回款 | `receivable` | `amount` | 回款 SoT |
| 进粉 | `daily_report` | `conversions` | 用于计算应收 |
| 项目 | `project` | `unit_price`, `owner_id` | 单价、负责人 |

### 2.2 字段清单 (MASTER.md §6.5)

**页面 2：资金总览 - 必须字段**

| 字段 | 来源 | 口径 | 必须 | 当前状态 |
|------|------|------|------|---------|
| 累计充值 | topup_record | `SUM(amount WHERE status='completed')` | :white_check_mark: | :construction: 待实现 |
| 累计消耗 | ad_spend_daily | `SUM(spend)` | :white_check_mark: | :construction: 待实现 |
| 当前余额 | 计算 | `累计充值 - 累计消耗` | :white_check_mark: | :construction: 待实现 |
| 应收款 | 计算 | `SUM(conversions × unit_price) - 累计回款` | :white_check_mark: | :construction: 待实现 |
| 资金占用 | 计算 | `累计充值 - 累计回款` | :o: | :construction: 待实现 |

**扩展字段 (可选)**

| 字段 | 来源 | 口径 | 说明 |
|------|------|------|------|
| 累计回款 | receivable | `SUM(amount WHERE status='received')` | 已回款总额 |
| 回款率 | 计算 | `累计回款 / 应收款总额 × 100%` | 回款效率 |
| 资金周转率 | 计算 | `累计消耗 / 平均资金占用` | 资金效率 |

### 2.3 计算公式 (MASTER.md §4.5.5)

```python
# 账户余额
账户余额 = SUM(topup_record.amount) - SUM(ad_spend_daily.spend)

# 累计充值
累计充值 = SUM(topup_record.amount WHERE status='completed')

# 累计消耗
累计消耗 = SUM(ad_spend_daily.spend)

# 累计回款
累计回款 = SUM(receivable.amount WHERE status='received')

# 应收款
应收款 = SUM(daily_report.conversions × project.unit_price) - 累计回款

# 资金占用
资金占用 = 累计充值 - 累计回款
```

### 2.4 边界场景处理

| 场景 | 处理规则 | 显示 |
|------|---------|------|
| unit_price 为空 | 该项目不计入应收 | 标记"待定价" |
| 回款 > 应收 | 允许，标记"超额回款" | 正常显示 |
| 余额为负 | 允许，高亮警告 | 红色显示 |
| 无充值记录 | 显示 0 | ¥0 |

|------|------|------|------|
| 获取资金概览 | GET | `/api/v1/fund/overview` | 核心指标汇总 |
| 获取资金分布(按项目) | GET | `/api/v1/fund/distribution/projects` | 项目维度 |

| 获取回款记录 | GET | `/api/v1/fund/payments` | 已回款列表 |

### 5.2 接口详情

```json
  "message": "success"
}
```

**请求参数**:
