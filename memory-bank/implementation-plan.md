## 1. 开发阶段总览

### Phase 1 (照亮阶段) - MVP 核心
> **原则**: 记录事实、展示状态、提示异常，**不强制阻断**

```
[M1 认证] → [M2 用户] → [M3 项目] ──→ [M5 账户]
                 ↓              ↓           ↓
              [M4 渠道] ───────┘       [M6 日报 P1]
                 ↓                          ↓
              [M7 充值] ←──────────────────┘
                 ↓
              [M8 账本]
                 ↓
              [M10 利润]
                 ↓
              [M11 周报]
```

**关键路径**: M1 → M2 → M3 → M5 → M6 → M8 → M10

### Phase 2 (自动化阶段) - 增强功能
> **原则**: 引入约束、强制审批、考核关联

- M6 日报完整版 (8 状态机)
- M9 对账批次管理

## 6. 质量门禁

### 任务卡完成标准
| 检查项 | 必须 |
|--------|------|
| 代码通过 `ruff check` | ✅ |
| 单元测试覆盖率 > 80% | ✅ |
| 无 supervisor 角色 | ✅ |
| 状态值在 STATE_MACHINE.md 中 | ✅ |
| 错误码在 ERROR_CODES.md 中 | ✅ |
| API 响应格式符合 API_SOT.md | ✅ |

## 7. 风险管理

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| AI 幻觉生成错误角色 | 高 | 提示词包含 6 角色白名单 |
| 状态值不在枚举中 | 高 | 对照 STATE_MACHINE.md |
| 需求变更 | 中 | 每周 Review，SoT 驱动 |
| 字段名不一致 | 中 | 对照 DATA_SCHEMA.md |
