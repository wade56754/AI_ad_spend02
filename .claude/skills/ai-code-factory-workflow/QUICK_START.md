# AI 代码工厂工作流 - 快速开始

> **版本**: v5.1  
> **更新日期**: 2026-01-09

## 在 Claude/Cursor 中使用

### 方式一：直接使用自然语言（推荐）

直接在对话框中输入你的需求，系统会自动识别并调用相应的工作流：

#### 示例 1: 创建功能

```
创建一个用户管理功能，包括：
1. 后端 API：列表（分页、搜索）、创建、编辑、删除
2. 前端页面：用户列表、创建表单、编辑表单
3. 数据验证：用户名唯一、邮箱格式
4. 权限控制：只有管理员可以删除
```

#### 示例 2: 代码审查

```
审查用户管理模块的代码质量和安全性
```

#### 示例 3: Bug 修复

```
修复用户登录功能的问题：
用户输入错误密码 3 次后，账户被锁定，但解锁逻辑有问题
```

#### 示例 4: 性能优化

```
优化用户列表查询性能，当前查询 1000 条记录需要 5 秒，目标优化到 1 秒以内
```

#### 示例 5: 系统架构

```
设计微服务架构方案，包括用户服务、订单服务、支付服务
```

### 方式二：明确指定工作流

如果自动识别不准确，可以明确指定工作流类型：

```
使用代码工厂工作流，类型：全栈开发
需求：创建一个订单管理功能
```

```
使用代码工厂工作流，类型：代码审查
需求：审查充值模块的代码
```

## 支持的工作流类型

| 工作流类型 | 触发词 | 说明 |
|-----------|--------|------|
| `full_stack_development` | "创建"、"开发"、"实现" | 全栈功能开发 |
| `code_review` | "审查"、"检查"、"review" | 代码审查 |
| `bug_fixing` | "修复"、"bug"、"问题" | Bug 修复 |
| `performance_optimization` | "优化"、"性能"、"慢" | 性能优化 |
| `system_architecture` | "架构"、"设计" | 系统架构 |

## 注意事项

1. **API 密钥**: 如果没有设置 `ANTHROPIC_API_KEY`，系统会使用模拟模式（返回模拟结果）
2. **需求描述**: 尽量清晰具体，包含功能点、技术要求、特殊要求
3. **工作流选择**: 系统会自动识别，如果不准确可以明确指定

## 故障排查

### 问题：无法识别工作流类型

**解决**: 明确指定工作流类型，例如：
```
使用代码工厂工作流，类型：全栈开发
需求：...
```

### 问题：执行失败

**解决**: 
1. 检查 `ANTHROPIC_API_KEY` 环境变量
2. 查看错误信息
3. 简化需求重新尝试
