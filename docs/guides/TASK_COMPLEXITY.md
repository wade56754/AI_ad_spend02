# 任务复杂度分级指南

> **版本**: v1.0
> **更新日期**: 2025-12-29
> **适用范围**: AI 编程任务复杂度评估

---

## 概述

本指南定义了四级任务复杂度分类系统，用于指导 AI 编程工作流程选择。
不同复杂度的任务需要不同的验证深度和流程步骤。

---

## 复杂度分级

### L1 - 快速修复 (Quick Fix)

**特征**:
- 单文件修改
- 无业务逻辑变更
- 无状态/角色相关

**示例**:
- Typo 修复
- 简单样式调整
- 注释更新
- import 语句修复

**推荐流程**:
```
直接执行 → 验证 → 提交
```

**验证清单**:
- [ ] TypeScript/Python 编译通过
- [ ] 无 lint 错误

**Memory Bank 更新**: 无需更新

---

### L2 - 简单增强 (Simple Enhancement)

**特征**:
- 1-3 个文件修改
- 遵循现有模式
- 无状态机变更
- 无角色权限变更

**示例**:
- 添加表格列
- 添加表单字段
- 修改文案/标签
- 添加简单 API 参数

**推荐流程**:
```
SoT 查阅 → 执行 → 验证 → 提交
```

**验证清单**:
- [ ] TypeScript/Python 编译通过
- [ ] 无 lint 错误
- [ ] 字段类型符合 DATA_SCHEMA.md
- [ ] 状态值在 STATE_MACHINE.md 中

**Memory Bank 更新**:
- 更新 `progress.md`

---

### L3 - 功能开发 (Feature Development)

**特征**:
- 多文件修改 (>3 个)
- 新增 API 端点
- 新增功能模块
- 涉及业务规则

**示例**:
- 新增 CRUD 接口
- 新增功能页面
- 新增 React Query hook
- 添加表单验证逻辑

**推荐流程**:
```
Plan Mode → SoT 验证 → 分步执行 → 单元测试 → 提交
```

**验证清单**:
- [ ] TypeScript/Python 编译通过
- [ ] 无 lint 错误
- [ ] API 端点在 API_SOT.md 中定义
- [ ] 角色在 6 角色白名单中
- [ ] 状态值在 STATE_MACHINE.md 中
- [ ] 错误码在 ERROR_CODES_SOT.md 中
- [ ] 单元测试覆盖

**Memory Bank 更新**:
- 更新 `progress.md`
- 更新 `architecture.md`（如有新文件）

---

### L4 - 架构变更 (Architecture Change)

**特征**:
- 影响多个模块
- 状态机变更
- 数据库结构变更
- 角色权限变更
- 核心公式变更

**示例**:
- 新增/修改状态机
- 数据库表结构变更
- 新增角色或权限
- 核心算法重构
- 多模块重构

**推荐流程**:
```
OpenSpec 流程 → 设计审批 → 分步实施 → 回归测试 → 代码审查 → 提交
```

**验证清单**:
- [ ] OpenSpec change 已创建
- [ ] proposal.md 已审批
- [ ] TypeScript/Python 编译通过
- [ ] 无 lint 错误
- [ ] 回归测试全部通过
- [ ] SoT 文档已同步更新
- [ ] 数据库迁移脚本已生成

**Memory Bank 更新**:
- 更新 `progress.md`
- 更新 `architecture.md`
- 更新 `implementation-plan.md`（如有计划变更）

## 标签使用规范

在任务描述或提交信息中使用以下标签：

| 标签 | 含义 | 示例 |
|------|------|------|
| `[L1]` | 快速修复 | `[L1] 修复 typo` |
| `[L2]` | 简单增强 | `[L2] 添加日报表格状态列` |
| `[L3]` | 功能开发 | `[L3] 实现充值申请 API` |
| `[L4]` | 架构变更 | `[L4] 日报状态机升级为 8 状态` |

**提交信息示例**:
```bash
# L1
git commit -m "[L1] fix: 修复登录页面 typo"

# L2
git commit -m "[L2] feat: 添加日报表格创建时间列"

# L3
git commit -m "[L3] feat(api): 实现充值申请 CRUD 接口"

# L4
git commit -m "[L4] feat(core): 日报状态机升级为 8 状态 [change-id: report-sm-v2]"
```

## 与现有流程的关系

### 与 SoT 裁判链的关系

| 复杂度 | SoT 查阅范围 |
|--------|-------------|
| L1 | 无需查阅 |
| L2 | DATA_SCHEMA.md, STATE_MACHINE.md |
| L3 | + API_SOT.md, BUSINESS_RULES.md, ERROR_CODES_SOT.md |
| L4 | 全部 SoT + OpenSpec 流程 |

### 与 OpenSpec 的关系

| 复杂度 | OpenSpec 要求 |
|--------|---------------|
| L1 | 不需要 |
| L2 | 不需要 |
| L3 | 可选（如涉及 API 新增） |
| L4 | **强制要求** |

### 与回归测试的关系

| 复杂度 | 回归测试要求 |
|--------|-------------|
| L1 | 不需要 |
| L2 | 相关模块测试 |
| L3 | 相关模块测试 + 集成测试 |
| L4 | **五连拍回归测试** |

## AI 助手使用指南

当 AI 助手接收任务时，应先评估复杂度：

```markdown
## 任务复杂度评估

**任务**: [任务描述]

**评估结果**: L[1-4]

**理由**:
- [ ] 涉及状态机变更: 是/否
- [ ] 涉及角色权限变更: 是/否
- [ ] 涉及数据库变更: 是/否
- [ ] 文件修改数量: N 个
- [ ] 是否新增 API: 是/否

**选择的流程**: [对应流程]
```
