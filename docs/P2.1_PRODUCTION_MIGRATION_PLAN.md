# P2.1 生产环境角色迁移执行手册

> **任务目标**: 将生产环境 users 表中的历史角色（user、manager、operator、viewer）迁移为新的 5 角色枚举
> **执行环境**: 生产环境（⚠️ 高风险）
> **执行时机**: 待定（需在 P2.2 之前执行）
> **风险等级**: 🔴 高（涉及生产数据修改）

---

## ⚠️ 执行前置条件

### 必须满足的条件
1. ✅ **已在生产数据库备份副本上完整验证**此脚本
2. ✅ **已获得数据库管理员授权**
3. ✅ **已通知相关业务团队**（预留维护窗口）
4. ✅ **已准备回滚方案**（包含完整数据库备份）
5. ✅ **已确认低峰期执行窗口**（建议凌晨 2:00-5:00）
6. ✅ **P2.2 尚未执行**（CHECK 约束会阻止迁移）

### ⚠️ 如果任一条件不满足，禁止执行

### 步骤 2: 在备份副本上执行完整迁移（DRY RUN）

```sql
-- ============================================================
-- ⚠️ 仅在备份副本上执行
-- ============================================================

BEGIN;

-- 创建迁移日志表
CREATE TEMP TABLE role_migration_log (
    user_id UUID,
    email TEXT,
    old_role TEXT,
    new_role TEXT,
    migrated_at TIMESTAMP DEFAULT NOW()
);

-- 记录迁移前状态
INSERT INTO role_migration_log (user_id, email, old_role, new_role)
SELECT
    id,
    email,
    role,
    CASE
        WHEN role = 'user' THEN 'media_buyer'
        WHEN role = 'manager' THEN 'account_manager'
        WHEN role = 'operator' THEN 'data_operator'
        WHEN role = 'viewer' THEN 'media_buyer'
        ELSE role
    END
FROM users
WHERE role IN ('user', 'manager', 'operator', 'viewer');

-- 查看迁移计划
SELECT * FROM role_migration_log ORDER BY old_role, email;

-- 执行迁移
UPDATE users
SET role = 'media_buyer', updated_at = NOW()
WHERE role = 'user';

UPDATE users
SET role = 'account_manager', updated_at = NOW()
WHERE role = 'manager';

UPDATE users
SET role = 'data_operator', updated_at = NOW()
WHERE role = 'operator';

UPDATE users
SET role = 'media_buyer', updated_at = NOW()
WHERE role = 'viewer';

-- 验证迁移结果
SELECT
    old_role,
    new_role,
    COUNT(*) AS migrated_count
FROM role_migration_log
GROUP BY old_role, new_role
ORDER BY old_role;

-- 验证无历史角色残留
SELECT COUNT(*) AS remaining_old_roles
FROM users
WHERE role IN ('user', 'manager', 'operator', 'viewer');
-- 预期: 0

-- 验证所有用户角色合法
SELECT COUNT(*) AS invalid_roles
FROM users
WHERE role NOT IN ('admin', 'finance', 'account_manager', 'data_operator', 'media_buyer');
-- 预期: 0

-- ⚠️ 备份副本验证：回滚（不提交）
ROLLBACK;

-- 再次执行并提交（如果验证通过）
```

```sql
-- ============================================================
-- P2.1 生产环境角色迁移脚本
-- 执行环境: 生产环境
-- 执行人: _____________
-- 执行日期: _____________
-- 执行时间: __:__
-- ============================================================

BEGIN;

-- 1. 创建迁移日志表（永久表，用于审计）
CREATE TABLE IF NOT EXISTS role_migration_audit (
    id SERIAL PRIMARY KEY,
    user_id UUID NOT NULL,
    email TEXT NOT NULL,
    old_role TEXT NOT NULL,
    new_role TEXT NOT NULL,
    migrated_at TIMESTAMP DEFAULT NOW(),
    migrated_by TEXT DEFAULT current_user,
    migration_session TEXT DEFAULT 'P2.1_PRODUCTION'
);

-- 2. 记录迁移前状态
INSERT INTO role_migration_audit (user_id, email, old_role, new_role)
SELECT
    id,
    email,
    role,
    CASE
        WHEN role = 'user' THEN 'media_buyer'
        WHEN role = 'manager' THEN 'account_manager'
        WHEN role = 'operator' THEN 'data_operator'
        WHEN role = 'viewer' THEN 'media_buyer'
        ELSE role
    END
FROM users
WHERE role IN ('user', 'manager', 'operator', 'viewer');

-- 3. 显示迁移计划
SELECT
    old_role,
    new_role,
    COUNT(*) AS user_count
FROM role_migration_audit
WHERE migration_session = 'P2.1_PRODUCTION'
GROUP BY old_role, new_role
ORDER BY old_role;

-- ⚠️ 人工确认：迁移用户数是否符合预期？
-- 如果不符合，执行 ROLLBACK; 并调查

-- 4. 执行迁移：user → media_buyer
UPDATE users
SET role = 'media_buyer', updated_at = NOW()
WHERE role = 'user';

-- 验证
DO $$
DECLARE
    expected_count INTEGER;
    actual_count INTEGER;
BEGIN
    SELECT COUNT(*) INTO expected_count
    FROM role_migration_audit
    WHERE old_role = 'user' AND migration_session = 'P2.1_PRODUCTION';

    SELECT COUNT(*) INTO actual_count
    FROM users
    WHERE role = 'media_buyer'
      AND id IN (
          SELECT user_id FROM role_migration_audit
          WHERE old_role = 'user' AND migration_session = 'P2.1_PRODUCTION'
      );

    IF actual_count != expected_count THEN
        RAISE EXCEPTION '迁移验证失败: user → media_buyer (预期: %, 实际: %)', expected_count, actual_count;
    ELSE
        RAISE NOTICE '✅ user → media_buyer 迁移成功 (% 个用户)', actual_count;
    END IF;
END $$;

-- 5. 执行迁移：manager → account_manager
```

## 🔄 回滚方案

### 场景 A: 迁移过程中发现错误（事务内）

```sql

ROLLBACK;

-- 验证回滚成功

    role,
    COUNT(*) AS user_count
FROM users
WHERE role IN ('user', 'manager', 'operator', 'viewer')
GROUP BY role;
-- 应恢复到迁移前的数量
```

### 场景 B: 迁移已提交，但业务验证失败（需从备份恢复）

```sql
-- ⚠️ 此场景需要从数据库备份恢复
-- 1. 停止应用服务器（避免新数据写入）
-- 2. 从备份恢复 users 表
-- 3. 验证数据完整性
-- 4. 重启应用服务器
-- 5. 通知相关团队

-- 如果仅需回滚角色字段（数据库仍可用）
BEGIN;

-- 从审计日志恢复角色
UPDATE users u
SET role = a.old_role, updated_at = NOW()
FROM role_migration_audit a
WHERE u.id = a.user_id
  AND a.migration_session = 'P2.1_PRODUCTION';

-- 验证回滚
SELECT
    role,
    COUNT(*) AS user_count
FROM users
WHERE role IN ('user', 'manager', 'operator', 'viewer')
GROUP BY role;
-- 应恢复到迁移前的分布

COMMIT;
```
