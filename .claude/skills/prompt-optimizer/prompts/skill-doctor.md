## 诊断维度

按以下维度评估生成的提示词：

| 维度 | 检查项 | 扣分标准 |
|------|--------|----------|
| **XML 规范** | 标签是否使用标准命名 (`role/goal/input/output_format/constraints`) | 非标准标签 -2 |
| **标签完整** | 是否包含必需标签 (`goal`, `output_format`) | 缺失必需 -5 |
| **格式闭合** | 代码块、表格是否完整闭合 | 未闭合 -3 |
| **约束明确** | 是否有数量、范围、优先级定义 | 缺失约束 -2 |
| **示例完整** | 输入输出示例是否完整可用 | 示例不完整 -2 |
| **异常处理** | 是否考虑边界情况 | 缺失 -1 |
| **领域适配** | 是否体现领域专业知识 | 过于通用 -2 |

## 常见缺陷模式

供诊断参考：

| 症状 | 根因 | 修复位置 |
|------|------|----------|
| 非标准 XML 标签 | `claude.md` 标签规范不强制 | 添加标签白名单 |
| 代码块未闭合 | `signature.md` 模板不完整 | 补全代码模板 |
| 缺少约束 | `signature.md` 无约束模板 | 添加约束示例 |
| 领域知识不足 | 缺少 `domains/xxx.md` | 创建领域文件 |
| 输出格式模糊 | `quality.md` 未检查输出完整性 | 添加检查项 |
| 无异常处理 | `intent.md` 未识别边界需求 | 补充隐式约束规则 |

## 执行要求

1. **逐条诊断**: 不要遗漏任何问题
2. **追溯根因**: 每个问题必须定位到 skill 的具体文件
3. **给出代码**: 修复方案必须是可直接使用的 Markdown 内容
4. **验证闭环**: 展示修复后的预期输出
