# PART 1: 概览

> 📖 **阅读时间**: 2分钟 | **目标读者**: 高管、决策者

## 1.1 TL;DR (30秒版本)

**我们是谁**: 一家广告代投公司，帮助广告主在 Facebook/TikTok 投放广告获取销售线索。

**核心问题**: 当前业务管理依赖 Excel + 微信群，导致：
- 项目盈亏不清晰，月底才能算出利润
- 投手日报散乱，提成计算需要3天
- 账户分配混乱，状态无法追溯
- 代理商押款不清，资金占用高

**解决方案**: 建设一套一体化管理系统，覆盖项目、投手、账户、渠道、财务五大模块。

**核心价值**: 
- 📊 实时掌握项目盈亏
- ⏱️ 提成计算从3天→10分钟
- 🔍 账户全生命周期可追溯
- 💰 押款实时监控，资金效率提升

## 2.1 商业模式

### 2.1.1 业务定位

```
┌─────────────────────────────────────────────────────────────────┐
│                      广告代投服务商                              │
│                                                                 │
│  上游：广告平台（Facebook、TikTok）                              │
│  中游：我们（专业投放团队 + 账户资源）                           │
│  下游：广告主（需要获客的企业）                                  │
│                                                                 │
│  核心价值：帮广告主获取销售线索，按效果收费                      │
└─────────────────────────────────────────────────────────────────┘
```

### 2.1.2 收入模式

| 模式 | 公式 | 适用场景 | 说明 |
|------|------|---------|------|
| **固定单价** | 收入 = 有效线索数 × 单价 | 标准化市场 | 每个项目单价不同 |
| **阶梯定价** | 收入 = Σ(各档位线索数 × 该档单价) | 高价值市场 | 每个项目档位配置不同 |
| **服务费** | 收入 = 消耗 × (1 + 费率) | 测试期 | 低风险模式 |

> ⚠️ **关键点**: 定价规则按项目配置，每个项目的单价/阶梯都不同，根据市场和成本确定

### 2.1.3 结算模式

```
┌─────────────────────────────────────────────────────────────────┐
│                         结算流程                                 │
│                                                                 │
│  1. 客户先打预付款 → 我们收到后记录入账                         │
│  2. 项目进行中 → 跟踪消耗和有效线索                             │
│  3. 项目结束时 → 计算最终收入 = 有效线索 × 单价                 │
│  4. 多退少补 → 与预付款对比，差额处理                           │
│                                                                 │
│  ⚠️ 关键：没有固定结算周期，项目结束时一次性结算                │
└─────────────────────────────────────────────────────────────────┘
```

### 2.1.4 利润公式

```
┌─────────────────────────────────────────────────────────────────┐
│                    财务计算公式（v5.2 修正）                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  【项目层面】                                                    │
│  项目总支出 = 平台广告消耗 × (1 + 代理商费率) + 开户费           │
│  项目毛利 = 客户实际收款 - 项目总支出                            │
│                                                                 │
│  【公司层面】                                                    │
│  公司毛利 = Σ 各项目毛利                                        │
│  运营成本 = 人力 + 办公 + 广告配套 + 其他                       │
│  公司净利润 = 公司毛利 - 运营成本 - 投手提成                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

⚠️ 关键原则：
- 收入以项目结束时最终确认为准
- 消耗以代理商账户实际消耗为准（不是投手申报数据）
- 手续费已包含在项目总支出中，不再单独从公司利润扣除
- 广告配套（主页、个号、BM、IP、邮箱、防护续费等）属于公司运营成本
```

## 2.3 核心数据流

### 2.3.1 消耗数据双轨制 ⭐

```
┌─────────────────────────────────────────────────────────────────┐
│                      消耗数据来源                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  数据源1: 投手申报消耗                                          │
│  ├── 来源：投手每日填报                                         │
│  ├── 用途：参考、趋势分析、异常预警                             │
│  └── 特点：及时但不够准确                                       │
│                                                                 │
│  数据源2: 实际消耗 ⭐（最终数据）                               │
│  ├── 来源：代理商广告账户后台                                   │
│  ├── 录入：户管定期从代理商处获取并录入                         │
│  ├── 用途：成本计算、押款计算、利润计算                         │
│  └── 特点：准确但有延迟                                         │
│                                                                 │
│  ⚠️ 关键规则：                                                  │
│  - 押款计算 = 累计充值 - 累计实际消耗                           │
│  - 项目总支出 = 实际消耗 × (1 + 代理商费率) + 开户费  ⭐新增    │
│  - 项目利润计算 = 收入 - 项目总支出（含手续费）                 │
│  - 投手申报消耗仅作参考，不作为财务依据                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.3.2 收入数据流

```
┌─────────────────────────────────────────────────────────────────┐
│                        收入确认流程                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  日常跟踪（预估）：                                              │
│  投手填进粉 → PM审核趋势 → PM确认有效线索 → 系统计算预估收入    │
│                                                                 │
│  最终确认（实际）：                                              │
│  项目结束 → PM确认最终有效线索数 → 财务手动录入最终收入         │
│             → 与预付款对比 → 多退少补                           │
│                                                                 │
│  ⚠️ 关键规则：                                                  │
│  - 日常显示的是"预估收入"                                       │
│  - 最终收入由财务手动录入                                       │
│  - 收入明细需要财务手动维护                                     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.3.3 资金流向

```
客户 ──(预付款)──→ 我们 ──(充值)──→ 代理商 ──(消耗)──→ 广告平台

三本账：
├── 预付款账本：客户付给我们的钱（负债）
│   └── 项目结束时：收入 > 预付款 → 客户补款
│                   收入 < 预付款 → 我们退款
├── 充值账本：我们充给代理商的钱（支出）
└── 押款：充值 - 实际消耗 = 押在代理商的钱（资金占用）
    └── 押款根据实际消耗实时计算
```

## 2.4 日报状态机 (8状态)

```
raw_submitted → trend_pending → trend_ok/trend_flagged 
                                        ↓
                               trend_resolved
                                        ↓
                               final_pending → final_confirmed → final_locked

状态说明：
├── raw_submitted: 投手提交日报
├── trend_pending: 等待PM审核趋势
├── trend_ok: PM审核通过（数据正常）
├── trend_flagged: PM标记异常（需要处理）
├── trend_resolved: 异常已处理
├── final_pending: 等待PM确认有效线索
├── final_confirmed: PM已确认
└── final_locked: 月度锁账（不可修改）
```

### 3.0.2 用户故事

#### Epic: 登录认证

**US-AUTH-001**: 用户登录
```
As a 任意角色用户
I want to 使用邮箱和密码登录系统
So that 访问我有权限的功能

Acceptance Criteria:
□ 输入邮箱和密码
□ 密码错误时显示错误提示，不透露具体是邮箱还是密码错误
□ 连续5次错误后锁定账号15分钟
□ 登录成功后跳转到对应角色的首页
□ 记住登录状态7天
```

**US-AUTH-002**: 用户登出
```
As a 已登录用户
I want to 安全退出系统
So that 保护账号安全

```
As a 已登录用户

### 3.5.3 利润计算规则 (v5.2 修正)

```
┌─────────────────────────────────────────────────────────────────┐
│                  利润计算规则 (v5.2 修正)                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  【项目层面】                                                    │
│  项目总支出 = 实际消耗 × (1 + 代理商费率) + 开户费              │
│  项目毛利 = 项目收入 - 项目总支出（含手续费）                   │
│                                                                 │
│  【公司层面】                                                    │
│  公司毛利 = Σ 各项目毛利                                        │
│  公司净利润 = 公司毛利 - 运营成本 - 投手提成                    │
│                                                                 │
│  计算说明：                                                      │
│  ├── 项目收入：财务手动录入的实际收入                           │
│  ├── 项目消耗：户管录入的实际消耗（非投手申报）                 │
│  ├── 代理商费率：按渠道配置（如星链7%、凤凰8%、华飞8%+0.6%等） │
│  ├── 开户费：部分代理商收取的固定费用                           │
│  ├── 运营成本：人力 + 办公 + 广告配套 + 其他                   │
│  └── 投手提成：系统计算的阶梯提成                               │
│                                                                 │
│  ⚠️ 关键变更：                                                  │
│  - 手续费已计入项目总支出，不再在公司层面单独扣除               │
│  - 广告配套（主页、个号、BM、IP、邮箱、防护续费）计入运营成本  │
│  - 日常显示的是"预估利润"（基于预估收入和申报消耗）            │
│  - 锁账后显示"实际利润"（基于实际收入和实际消耗）              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

# 附录

## A. 术语表

| 术语 | 定义 |
|------|------|
| **CPL** | Cost Per Lead，单个有效线索的成本 = 消耗÷有效线索 |
| **有效线索** | 客户确认的潜在客户（也称"进粉"、"有效粉"） |
| **申报消耗** | 投手每日填报的消耗数据，仅供参考 |
| **实际消耗** | 代理商广告账户的真实消耗，由户管从代理商后台获取并录入 |
| **预付款** | 客户提前支付的款项，用于项目结束时结算 |
| **押款** | 充值到代理商未消耗的余额 = 累计充值 - 累计实际消耗 |
| **渠道** | 代理商，广告账户的来源方 |
| **费率** | 代理商收取的手续费比例，按渠道配置 |
| **阶梯提成** | 按有效线索数量分档计算的提成模式 |
| **锁账** | 月末冻结数据，确保不被篡改 |
